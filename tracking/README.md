# متابعة مشروع معرض البركة

هذا الفولدر هو **مصدر الحقيقة** لحالة المشروع. لا تعتمد على الذاكرة أو المحادثات.

## الملفات

| الملف | الوظيفة |
|---|---|
| `progress.md` | وصلنا لإيه؟ المرحلة الحالية، العوائق، والخطوة التالية |
| `stages.md` | قائمة المراحل التنفيذية وحالتها |
| `changes.md` | سجل التغييرات والملفات المتأثرة |
| `tests.md` | خطة الاختبارات ونتائج التشغيل |
| `bugs.md` | الأخطاء والملاحظات المفتوحة والمغلقة |
| `decisions.md` | القرارات التقنية وقرارات العمل |
| `templates/` | قوالب موحدة للمرحلة والاختبار والخطأ والتغيير |

## دورة العمل

1. **قبل المرحلة:** تأكد أنها أول مرحلة غير مكتملة، وعلّمها 🟨 في `stages.md`.
2. **أثناء المرحلة:** سجّل أي قرار جديد في `decisions.md`، وأي عائق في `progress.md`.
3. **بعد المرحلة:**
   - علّمها ✅ في `stages.md`.
   - حدّث `progress.md`.
   - أضف سطرًا في `changes.md`.
   - أضف نتيجة الاختبار في `tests.md`.
   - أضف أي خطأ في `bugs.md`.
4. **لا تبدأ مرحلة تعتمد على أخرى غير مكتملة.**

## الحالات

| الرمز | المعنى |
|---|---|
| ⬜ | لم تبدأ |
| 🟨 | جارية |
| ✅ | مكتملة |
| ⛔ | متعطلة |
| 🔁 | تحتاج مراجعة |

## قواعد

- لا تُعد المرحلة مكتملة بدون اختبار موثق.
- كل تغيير له سطر في `changes.md`.
- كل اختبار له `Test ID`.
- كل خطأ له `BUG ID`.
- لا تحذف سجلًا؛ غيّر حالته واترك السبب.
- المراجع الأساسية: `../Requirements.md` و`../stages.md`.
